**Windows boot race: `pty` state not managed — 2026-09-23**

- Gejala: kadang muncul `Bentomux boot error: state not managed for field 'pty' on command 'tab_restore'` saat app dibuka ulang di Windows.
- Akar masalah: Tauri membuat window + WebView2 di dalam `setup()` sebelum closure `.setup(...)` app berjalan, dan IPC-nya datang dari thread WebView2. `AppStateManager` sudah di-`manage()` di Builder (fix `7107ea8`), tapi `PtyManager` masih di-`manage()` di dalam setup — setelah `PtyManager::new()` yang menjalankan handshake ke pty host daemon (spawn + tunggu sampai 6 detik, plus `restart_host` 4 detik). Kalau daemon harus di-spawn ulang (habis update atau habis idle-exit) handshake lambat, dan `tab_restore` menang balapan. Retry `get_state` (`46ec8d6`) tidak menolong: `get_state` sudah pre-managed sehingga sukses instan, lalu `restoreTabs()` yang gagal.
- `src-tauri/src/pty.rs`: `PtyManager::new()` kini I/O-free (aman dipanggil di Builder) dan `start(app)` yang menjalankan handshake, dipanggil dari setup. Ditambah gate kesiapan (`ready` + `Condvar`): command yang datang di tengah handshake menunggu, bukan membaca manajer kosong. Gate dibuka juga saat handshake gagal supaya command melapor `PTY host not connected` alih-alih menggantung; ada timeout 45 detik sebagai pengaman. Ini juga menutup bahaya kedua: `restore_terms` yang jalan sebelum transport siap akan membaca daftar live kosong, mengganti semua tab dengan shell baru, dan meninggalkan pane daemon sebagai yatim.
- Field `app` menjadi `Arc<OnceLock<AppHandle>>` dan reader thread membacanya saat emit, supaya `pty:data` / `pty:exit` yang terjadi sebelum setup selesai tetap sampai ke renderer.
- `restart_host` memakai `shutdown_host_now()` (tanpa gate) karena dipanggil dari dalam handshake; `shutdown_host()` publik tetap menunggu gate.
- Tes: `test_commands_wait_for_the_ready_gate` memastikan `live_terms` memblokir selama gate tertutup dan selesai setelah dibuka.
- Validasi PASS: `cargo check`, `npm run test:backend` (204 tests), `npm run typecheck`, `npm run build`.

**CSP nonce silenced every runtime-injected style (v0.2.32 → v0.2.34) — 2026-09-28**

- Symptom, reported against v0.2.32 and still present in v0.2.34: terminal panes render with no colours and no cell metrics, and the palette swatches in Settings are empty boxes. DevTools shows `Refused to apply a stylesheet because its hash, its nonce, or 'unsafe-inline' does not appear in the style-src directive` — one error per stylesheet, three per terminal.
- Root cause: the boot splash commit `f90223d` added the first inline `<style>` to `src/index.html`. Tauri stamps a nonce onto every inline `<style>` at build time (`tauri_utils::html2::inject_nonce_token`, `html2.rs:74-76`) and appends the matching `'nonce-…'` to `style-src` on every response (`tauri::manager::replace_csp_nonce`, `manager/mod.rs:125-151`). Per the CSP spec a directive carrying a nonce- or hash-source **ignores** `'unsafe-inline'`, so the `'unsafe-inline'` the config had always declared went inert the moment that first element appeared.
- Blast radius, both silent because `<link rel=stylesheet>` still matches `'self'`: xterm injects three `<style>` elements per terminal (`_themeStyleElement` carries every theme colour plus font-family/size, `_dimensionsStyleElement` carries cell height, plus the scrollbar sheet) — refused means no colours and no cell metrics. Inline `style=""` attributes are refused too, and `buildPaletteGrid` (`src/src/views/settings.ts:97`) builds each swatch that way, so the dots render as transparent 14px boxes.
- Why no test caught it: `devCsp` declares no `style-src` at all, so dev falls back to `default-src`, which has `'unsafe-inline'` and no nonce. `scripts/verify-splash.mjs` serves `out/renderer` from its own HTTP server, which never goes through the Tauri asset handler, so no nonce is ever stamped.
- `src-tauri/tauri.conf.json`: set `security.dangerousDisableAssetCspModification: ["style-src"]`, which skips the nonce injection for that directive only. `style-src` stays `'self' 'unsafe-inline' plugin: http://plugin.localhost` and `'unsafe-inline'` is honoured again. `script-src` keeps its nonces, so script injection is unaffected; what is given up is nonce protection of *inline style* (CSS UI redress), not code execution.
- `scripts/check-csp-inline-styles.mjs` (new, `npm run check:csp-inline-styles`): fails if `style-src` (or `style-src-elem`/`style-src-attr`) carries `'unsafe-inline'` while Tauri is still allowed to stamp a nonce, and fails if the flag is set to `true` rather than scoped to `style-src` — that variant would also strip the `script-src` nonces.
- Validation: `npm run typecheck`, `npm run build`, `cargo check`, and the new check both green and red (reverting the config makes it exit 1 with the reason).
